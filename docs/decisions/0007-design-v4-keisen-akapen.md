# ADR-0007: デザインv4「罫線帳と赤ペン」への全面改修

- 日付: 2026-10-01
- ステータス: 承認（Masaru指示「サイト構成・デザイン・UI/UXを改修。SEO/AIOは落とさず高める。賞を狙える品質で」）

## 背景

v3（E案: ニュースポータル×求人ポータル / 2026-07-07）は情報量は十分だったが、汎用ポータルの見た目で
サイト固有の個性がなく、タイポグラフィの階層も弱かった。流入はBing・AI検索が主（ADR-0006）で、
着地した読者に「本物の学習サイト」と伝わる第一印象と、読み進めやすさが課題。

## 選択肢

1. v3の微修正（余白・色調整のみ）— 低リスクだが個性の問題は解決しない
2. 全面改修（コンセプトから再設計）— 構造化データ・URL・内部リンクを維持したまま見た目とIAを刷新
3. 日本語Webフォントを全面採用 — 見た目は良いがCLS・速度の悪化リスク

## 決定

案2。コンセプトは「罫線帳と赤ペン」（docs/tone.md v4）。見出しのみ明朝Webフォントを `display=optional` で読み、
本文はOSゴシックのまま（案3の利点だけを取る）。

## 主な変更

- トークン v4（tokens.css）: 紙・方眼・墨藍・藍・朱。共通プリミティブ（.page-head/.sec-head/.post-list 等）をグローバル化
- ヘッダー: ヘッダー内検索窓（PC）、ナビ7項目＋スマホ用「検索」で4列×2段の格子（全項目常時表示）。「ホーム」はロゴに統合
- フッター: 全13テーマへのリンクを追加（内部リンク強化）
- トップ: ヒーロー（方眼＋赤ペン添削の模式図）→帳簿の一行→最初の3本→学習の時間割（7章×4レベル・セルに実本数と先頭記事）→テーマ→新着＋用語＋約束→分野別の書架
- 記事: 方眼の見出し帯（カテゴリ・レベル・**description を要約リードとして本文冒頭に表示**・更新/レビュー日・読了目安・出典等級の内訳）、PCは目次を右に追従、スマホは折りたたみ目次、読書進捗バー（CSSのみ）、出典を判子型の等級表示に
- 削除: TrustHighlights.astro / BeginnerRoadmap.astro（トップに統合）
- 書体の追加: Shippori Mincho B1（800のみ）・IBM Plex Mono（400/600）。いずれもSIL OFL。
  読込は本文末尾のインラインスクリプトから `<link>` を差し込む（head に置くと media=print / preload でも Lighthouse が描画ブロック扱いし、構造化データで head が大きい用語集一覧が 98→75 に落ちた）

## 根拠

- SEO/AIO不変条件: URL・title・description・canonical・robots・JSON-LD（Article/LearningResource/DefinedTerm/BreadcrumbList/CollectionPage/WebSite）・sitemap は無変更。`npm run seo` で検査
- 要約リードの表示: Google の AI 機能向けガイダンスは特別な最適化を求めず「人に役立つ、ページ上で見えるテキスト」を重視（https://developers.google.com/search/docs/appearance/ai-features 確認日: 2026-09-23 / A）。description を本文冒頭に見える形で置くことはこれに沿う
- ナビを隠さない: 隠すと利用率が下がる（NN/G・メモリ記録の調査）→スマホも全項目表示
- `display=optional`: フォントが間に合わない場合はフォールバックで確定し差し替えない＝レイアウトシフトを起こさない（CSS Fonts仕様の font-display の定義）

## 影響

- Google Fonts への外部リクエストが発生する（GA4で既にGoogleへ送信しているため、新たな送信先の追加ではない）
- OGP画像（ops/og/generate_og.mjs）は旧デザインのまま。必要なら別途刷新
- 新しいページを作るときは tokens.css の共通プリミティブを使う（Astroのstyleはファイル単位スコープのため）

## 検証結果（2026-10-02・ローカル gzip 配信で旧版と同条件比較）

- SEO要素: 全238ページで title/description/canonical/robots/JSON-LD 差分0。内部リンク 消失1（トップの検索チップ /search/?q=インサイダー・noindexページ）／追加2,903
- `npm run seo` 指摘0・`npm run validate` 警告0・390〜1440pxで横スクロール0
- Lighthouse（モバイル・シミュレーション）: トップ97 / 学習マップ97 / 記事97 / テーマ97 / 書籍96 / チャート97、a11y・BP・SEOは全て100、CLS 0
- 例外: 用語集一覧 89（旧版98）。実測（observed）FCPは0.23秒で、Webフォント取得をシミュレーションが初回描画の依存に数えるため。本番の実測で再確認する
- 独立レビュー: UIレビュー 7.0/10 → 高優先の指摘（SPのCTA位置・ヒーロー要素過多・傍線過多・SPの縦長）を反映。コードレビュー 中2・低2 → 全件修正（時間割のARIA role、最初の3本の並び順、目次の助数詞、Pagefind索引へのヘッダー混入）
